# PULSE AI: Beyond the Scoreline

**Every moment has a story. Every story has evidence.**

PULSE AI turns synthetic football match events into live momentum visualisation, evidence-grounded explanations, AI commentary verification, a bounded multi-agent post-match debate, and personalised recaps. Built for the Microsoft x Premier League "Inside the Game" Developer Hackathon 2026 (Synthetic Match Insights Engine category).

All clubs (North City FC, South United FC), players, pundits and match data are fictional and generated by this repository. No real league data, footage, crests or trademarks are used.

| Section | What it does |
| --- | --- |
| **Live Match** | Scoreboard, clock, replay controls (play, pause, speeds 1x to 300x, scrubber, jump to goal or momentum shift), Match Pulse chart, event feed, server-computed statistics, pitch map, latest insights |
| **Match Pulse** | Deterministic momentum index with detected moments; click a marker to see what happened, why it was flagged, contributing event ids, statistics, and an AI explanation that is itself checked by Narrative VAR |
| **Narrative VAR** | Paste or pick commentary; claims are extracted, evidence retrieved from the event log, numbers checked by code, verdict shown with the kit's six statuses, before/after correction, evidence list and audit trail |
| **AI Studio** | Alex Mercer (Analyst), Mateo Reyes (Fan) and Sofia Hart (Tactician) debate Player of the Match in two bounded rounds; every argument is fact-checked; a moderator gives an evidence-based verdict or an acknowledged disagreement |
| **Match Recap** | Fan and Analyst modes (English, Spanish optional), key events, momentum timeline, verified insight sections, player table, Player of the Match |

## Quick start

Prerequisites: Python 3.11+ (tested on 3.14), Node 20+ (tested on 26), `uv` or `pip`.

```bash
# 1. Backend
cd pulse-ai
uv venv .venv && source .venv/bin/activate          # or: python -m venv .venv
uv pip install -r backend/requirements.txt           # or: pip install -r backend/requirements.txt
cd backend && uvicorn app.main:app --reload --port 8000

# 2. Frontend (new terminal)
cd pulse-ai/frontend
npm install
npm run dev                                          # http://127.0.0.1:5173 (proxies /api to :8000)
```

Open http://127.0.0.1:5173, pick a scenario, press **Start replay**, choose **300x** to see a whole match in 18 seconds, or use the **Jump to** chips.

The app runs fully in **Demo mode** without any Azure resources. The badge in the header shows the active AI mode at all times.

## How Microsoft Foundry and Agent Framework are used

Two providers implement one interface (`backend/app/ai/provider.py`):

- **Demo mode** (default when no endpoint is configured): deterministic, template-based text built only from computed statistics. Labelled `demo` in every API response and in the UI.
- **Foundry mode**: `azure-ai-projects` 2.x `AIProjectClient(endpoint, DefaultAzureCredential).get_openai_client()` and the **Responses API** (`responses.create(model=FOUNDRY_MODEL, ...)`) generate insight explanations, the moderator summary and recap summaries as JSON. In the **AI Studio**, each pundit is a **Microsoft Agent Framework** `Agent` bound to `agent_framework.foundry.FoundryChatClient` with its own persona instructions; the three agents run concurrently for the opening round, then one rebuttal round, then the moderator closes. Rounds are hard-bounded (2). If a call fails or times out, the system degrades to demo text and says so.
- **Safety contract in both modes**: models only ever receive an evidence pack computed by code (statistics, real event ids). Model text never overwrites authoritative statistics, and every generated sentence is passed through **Narrative VAR** before it reaches the UI. An unavailable model never results in a "verified" label.
- **Evaluation**: `python -m app.evaluation.run_eval` runs 69 labelled fixtures deterministically (see `docs/evaluation.md`). With `--foundry` and `ENABLE_GROUNDEDNESS_EVALUATOR=true`, the `azure-ai-evaluation` `GroundednessEvaluator` is also run and its raw output stored. The report lists exactly which evaluators ran.

### Configure Foundry

```bash
cp .env.example .env
# set FOUNDRY_PROJECT_ENDPOINT=https://<resource>.services.ai.azure.com/api/projects/<project>
# set FOUNDRY_MODEL=<deployment name>
az login          # or AZURE_CLIENT_ID / AZURE_TENANT_ID / AZURE_CLIENT_SECRET
```

Restart the backend. `GET /api/system/capabilities` and the header badge report `Foundry live` once a credential resolves. `PULSE_AI_MODE=demo` forces demo; `PULSE_AI_MODE=foundry` refuses to start in demo.

Honest status: this repository was developed without Azure credentials available in the build environment. The Foundry and Agent Framework code paths use the current SDK APIs (azure-ai-projects 2.9, agent-framework 1.19) and are exercised for configuration, fallback and JSON parsing in tests, but live inference has not been run here. Demo mode is complete and tested.

## Tests

```bash
# Backend: simulator integrity, analytics, Narrative VAR, agents, provider resolution
cd backend && source ../.venv/bin/activate && python -m pytest -q
python -m app.evaluation.run_eval                     # 69 labelled Narrative VAR cases

# Frontend
cd frontend
npm run typecheck                                     # tsc --strict (includes the brand-kit components)
npm test                                              # vitest: kit components, chart click, replay engine
npm run build                                         # production build to dist/
npm run e2e                                           # Playwright smoke test (needs both dev servers running)
```

Latest results (October 24, 2026): backend 54 passed, evaluation 69/69, vitest 5 passed, Playwright 5 passed, `tsc -b` clean, `vite build` clean.
